# Mock-сервер и проверка контракта

Набор файлов для задания 4: поднять Mock-сервер из `api/openapi.yaml`, прогнать запросы и получить доказательства.

| Файл | Назначение |
|---|---|
| `campus-events.postman_collection.json` | 8 запросов: успешные ответы и четыре класса ошибок. Импортируется в Bruno и Postman |
| `smoke.py` | автоматический прогон тех же сценариев, пишет `transcript.md` |
| `transcript.md` | протокол: запрос, ответ, код, время — готовый артефакт для отчёта |

## 1. Поднять Mock-сервер

Аккаунт не нужен, всё локально. Нужен только Node.js:

```powershell
cd D:\大四上\ПЧМИ\LAB4
npx --yes @stoplight/prism-cli mock api/openapi.yaml -p 4010
```

Вывод заканчивается строкой `Prism is listening on http://127.0.0.1:4010` — сервер готов.
Проверка в другом окне:

```powershell
curl.exe "http://127.0.0.1:4010/events?size=2"
```

## 2. Автоматический прогон

```powershell
python api\mock\smoke.py
```

Скрипт проходит восемь сценариев и перезаписывает `transcript.md`.
Ожидаемый итог — `Пройдено 8 из 8`.

## 3. Скриншоты в Bruno (то, что требует методичка)

1. Открыть Bruno → **`Import Collection`** → **`Postman Collection`** → выбрать `api/mock/campus-events.postman_collection.json`.
2. В левом дереве появится папка **Campus Events — Mock (ЛР № 4)** с тремя группами.
3. Выбрать окружение: значок шестерёнки в правом верхнем углу → **`Environments`** → добавить переменную `baseUrl = http://localhost:4010` (в коллекции уже стоит значение по умолчанию).
4. Открыть запрос **`04 Мест нет — 409 NO_SEATS`** → нажать **`Send`**.
   В панели справа будет `409 Conflict` и тело `{"code": "NO_SEATS", ...}` — **это первый скриншот**.
5. Повторить для **`02 Создание мероприятия — 201`** (ответ `201`) и **`06 Чужая организация — 403 NOT_OWNER`** (ответ `403`).
6. Четвёртый, необязательный скриншот — **`01 Афиша — 200`**: список с пагинацией.

Скриншота три: **201**, **409**, **403**. На каждом должно быть видно адрес `localhost:4010`, статус и тело ответа.

## 4. То же в Postman

`Import` → выбрать файл коллекции → `Send`. Логика та же, переменные уже внутри коллекции.

## 5. Вариант без локального запуска: SwaggerHub

Если нужен «облачный» Mock, а не локальный:

1. Зарегистрироваться на swaggerhub.com → **`Create New`** → **`Import and Document API`** → загрузить `api/openapi.yaml`.
2. На странице API нажать **`Mock Server`** — появится адрес вида `https://virtserver.swaggerhub.com/<логин>/campus-events/1.0.0`.
3. SwaggerHub выбирает ответ параметром **`__code`**: `.../events?__code=403`, `.../sessions/{id}/registrations?__code=409`.

## Как выбирается код ответа

По умолчанию Mock-сервер отдаёт первый успешный ответ из контракта. Чтобы получить конкретную ошибку, в запрос добавляется заголовок:

```
Prefer: code=409
```

Prism понимает этот заголовок и отдаёт ровно тот ответ, который описан для этого кода в `openapi.yaml`. Поэтому проверка воспроизводима: не «иногда повезло поймать 500», а заранее известный сценарий.

Дополнительно Mock-сервер сам проверяет запрос по контракту: если у операции требуется токен, а заголовка `Authorization` нет, вернётся `401` — именно так получается сценарий `05 Без токена — 401`.

## Что проверено

| Сценарий | Код | Тело |
|---|---|---|
| Афиша с пагинацией | 200 | `items`, `total`, `page` |
| Создание черновика мероприятия | 201 | карточка `Event` |
| Запись на сессию | 201 | `status: Записан` |
| Запись при заполненной сессии | 409 | `code: NO_SEATS` |
| Запрос без токена | 401 | `code: TOKEN_EXPIRED` |
| Заявки модерации чужой организации | 403 | `code: NOT_OWNER` |
| Пустое обязательное поле | 422 | `code: VALIDATION_FAILED` |
| Превышение лимита | 429 | `code: RATE_LIMITED` |
