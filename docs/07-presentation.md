## Что методичка требует от презентации

| Требование | Где отражено |
|---|---|
| Распределение задач в команде | слайд 3 — таблица «задание → содержание → артефакт → исполнитель» |
| Требования к приложению | слайды 2 и 4 — границы работы, 16 историй, 20 вариантов использования |
| Схема базы данных | слайды 6 и 7 — ER-диаграмма, 14 таблиц, триггеры-инварианты |
| Как организована работа с репозиторием | слайд 10 — ветки, коммиты, Projects, wiki, Pages |

## Содержание по слайдам

1. **Титул** — тема, группа, исполнитель.
2. **Границы работы** — какие задания обязательны для группы 13, что взято из ЛР № 3.
3. **Распределение работ** — шесть строк: задания 1–5 и документация.
4. **Задание 1** — реестр «актор — история — вариант использования», три добавленных API-сценария, 23 → 29 методов.
5. **Архитектура** — клиенты, контракт `/api/v1`, PostgreSQL; MCP-сервер на той же базе.
6. **Задание 2** — 14 таблиц, 103 поля, 13 перечислений, ER-диаграмма.
7. **Задание 2** — инварианты в СУБД: места, повторная запись, неизменяемые решения модерации, 15 проверок.
8. **Задания 3–4** — 29 операций, коды ошибок, идемпотентность, валидатор, Mock-сервер.
9. **Задание 5** — 3 инструмента, 2 ресурса, 1 шаблон промпта, структурные ошибки.
10. **Работа с репозиторием** — `main`, коммиты по заданиям, доска Projects, wiki, GitHub Pages.
11. **Проверяемость** — команда на каждое число в отчёте.
12. **Итоги** — что закрыто, какие ограничения остались.

## Пересборка

```bash
python tools/gen_deck.py
# HTML собирается в assets/presentation.html, затем печатается в PDF:
msedge --headless=new --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="assets/presentation.pdf" "file:///<путь>/assets/presentation.html"
```

Размер страницы задан в CSS (`@page { size: 297mm 210mm }`), поэтому PDF сразу получается в формате 16:9 — 12 страниц, без колонтитулов браузера. Числа в слайдах не вписаны руками: они соответствуют `docs/02`, `db/schema.sql`, `api/openapi.yaml` и `mcp/server.py`.
