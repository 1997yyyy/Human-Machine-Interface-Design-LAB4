# Задание 3. Маршруты и конечные точки API

Базовый путь — `/api/v1`, формат — JSON (UTF-8), аутентификация — JWT в заголовке
`Authorization: Bearer`, который выдаётся после проверки тикета CAS.
Стиль — REST, существительные во множественном числе, вложенность не глубже двух уровней.

Полная спецификация в читаемом виде — [api/index.html](../api/index.html): 29 операций
с параметрами, телами запросов и кодами ответов. Исходник — `api/openapi.yaml`.

## 1. Маршруты сущностей

Таблица связывает таблицу базы данных с ресурсом API. Правило: одна таблица —
один ресурс; связующие таблицы без собственного жизненного цикла отдельного
маршрута не получают и адресуются через владельца.

| Сущность | Таблица БД | Маршрут | Обоснование |
|---|---|---|---|
| Клуб | `club` | `/clubs` | Корневой ресурс, доступен без входа |
| Категория | `category` | `/categories` | Справочник, только чтение |
| Пользователь | `app_user` | `/users`, `/me` | `/me` — текущий пользователь, `/users/{id}` — администрирование |
| Членство | `membership` | `/clubs/{id}/members` | Не имеет смысла вне клуба |
| Мероприятие | `event` | `/events` | Корневой ресурс |
| Сессия | `session` | `/sessions` | Отдельный ресурс: запись ведётся на сессию |
| Регистрация | `registration` | `/registrations`, `/sessions/{sid}/registrations` | Создание в контексте сессии, управление — по собственному id |
| Билет | `ticket` | `/tickets` | Только чтение для студента, отметка — для организатора |
| Предложение места | `seat_offer` | `/seat-offers` | Отдельный ресурс: имеет срок жизни и своё состояние |
| Версия мероприятия | `event_version` | `/events/{id}/versions` | Только чтение, нужна модератору |
| Заявка на модерацию | `moderation_request` | `/moderation/requests` | Очередь администратора |
| Решение | `decision` | `/moderation/requests/{id}/decision` | Один объект на заявку, только создание |
| Отзыв | `review` | `/reviews` | Создаётся по мероприятию |
| Уведомление | `notification` | `/notifications` | Настройки каналов и история |

## 3. Коды ответов и машинные коды ошибок

Тело ошибки всегда одной формы, чтобы клиент не разбирал текст:

```json
{
  "code": "NO_SEATS",
  "message": "Свободных мест нет. Можно встать в лист ожидания.",
  "field": null,
  "trace_id": "b1f0c1e2-7f4a-4b07-9a3f-2f7d1f9d5c11"
}
```

| HTTP | Когда возникает | Машинные коды |
|---|---|---|
| 200 | Успешное чтение или изменение | — |
| 201 | Создан ресурс: регистрация, билет, мероприятие, клуб, отзыв | — |
| 204 | Удаление регистрации, отмена | — |
| 400 | Некорректный запрос: битый JSON, отсутствует обязательное поле пути | `BAD_REQUEST` |
| 401 | Нет токена или истёк срок | `UNAUTHENTICATED`, `TOKEN_EXPIRED` |
| 403 | Токен есть, но нет прав на объект (чужое мероприятие, чужая регистрация) | `FORBIDDEN`, `NOT_OWNER`, `ROLE_REQUIRED` |
| 404 | Объект не найден или скрыт от этой роли | `NOT_FOUND` |
| 409 | Конфликт состояния: мест нет, уже записан, билет уже использован, место уже занято | `NO_SEATS`, `ALREADY_REGISTERED`, `TICKET_USED`, `OFFER_EXPIRED`, `ALREADY_MODERATED` |
| 422 | Семантическая ошибка валидации полей | `VALIDATION_ERROR`, `TITLE_TOO_SHORT`, `SESSION_IN_PAST`, `COMMENT_TOO_SHORT` |
| 429 | Превышен лимит запросов на пользователя (100/мин) | `RATE_LIMITED` |
| 500 | Внутренняя ошибка | `INTERNAL` |

Правило разделения 401 и 403: 401 — «кто ты», 403 — «что тебе можно».
409 используется только там, где запрос корректен синтаксически, но нарушает
состояние системы; клиент в этом случае показывает не ошибку, а следующий шаг
(например, кнопку «Встать в лист ожидания»).

## 4. Идемпотентность

| Метод | Механизм |
|---|---|
| `POST /sessions/{sid}/registrations` | Частичный уникальный индекс `(session_id, user_id) WHERE status <> 'Отменено'`; повтор даёт 409 `ALREADY_REGISTERED` |
| `POST /checkins/batch` | Ключ идемпотентности `Idempotency-Key` + уникальность `ticket.qr_payload`; повторная отметка возвращает 200 с `alreadyMarked: true` |
| `POST /moderation/requests/{id}/decision` | Уникальность `decision.request_id`; повтор даёт 409 `ALREADY_MODERATED` |
| `PATCH /events/{id}` | Оптимистическая блокировка через `If-Match` с номером версии |
