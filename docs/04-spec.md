# Дополнительная спецификация

Ограничения, требования к безопасности, надёжности и совместимости. Числовые
критерии взяты из ЛР № 3 (раздел 8.6, NFR-01…36) и дополнены тем, что появилось
вместе с API и MCP-сервером.

## 1. Ограничения

| Ограничение | Значение | Причина |
|---|---|---|
| Язык интерфейса v1 | русский | Пилот на одном факультете |
| Аутентификация | только CAS/LDAP БГУ | Отдельных паролей в системе нет |
| Часовой пояс хранения | UTC, отображение — Europe/Minsk | Совпадение с расписанием корпусов |
| Максимум сессий у мероприятия | 3 | Больше не помещается в карточку без прокрутки |
| Глубина вложенности маршрутов | 2 уровня | `/sessions/{sid}/registrations` — предел |
| Размер тела запроса | 1 МБ, кроме загрузки афиши (5 МБ) | Защита от случайных дампов |
| Срок жизни предложения места | 30 минут | Успевает ответить человек, ждущий у экрана |
| Срок жизни JWT | 30 дней | Компромисс между удобством и риском |

## 2. Безопасность

**Аутентификация и авторизация.** Токен выдаётся только после проверки тикета CAS;
пароль не передаётся и не хранится. Роль проверяется на сервере для каждого
запроса, а не берётся из клиента. Владелец объекта проверяется отдельно от роли:
организатор видит только мероприятия своих клубов (`NOT_OWNER`, 403).

**Билет.** Подпись Ed25519 по строке `ticket_id|session_id|issued_at`; закрытый ключ
на сервере, открытый — в приложении организатора. В билете нет персональных данных:
по QR нельзя узнать ФИО, группу или почту. Ротация ключа не чаще раза в семестр,
старые версии проверяются ещё 30 дней (`session.qr_key_version`).

**Данные.** Выгрузки участников не содержат контактных данных — только ФИО,
группа, статус и время отметки. В MCP-сервере то же правило: ресурс
`registrations://user/{id}` отдаёт статусы и время, но не `email`.

**Транспорт.** TLS 1.2+, HSTS, CSP без `unsafe-inline`. Таймаут запроса — 10 секунд.

**Аудит.** Решения по заявкам неизменяемы: таблица `decision` защищена триггером,
любая попытка `UPDATE` или `DELETE` прерывается (`APPEND_ONLY`). Смена ролей
фиксируется в журнале с указанием администратора и причины.

## 3. Надёжность и целостность

| Правило | Как обеспечено |
|---|---|
| Активных записей не больше лимита | Триггер `registration_seat_insert` с блокировкой строки сессии `FOR UPDATE` |
| Одна активная запись на пару «пользователь — сессия» | Частичный уникальный индекс `(session_id, user_id) WHERE status <> 'Отменено'` |
| Одно активное предложение места на запись | Частичный уникальный индекс по `registration_id` при `status = 'Выдано'` |
| `0 ≤ taken ≤ capacity` | `CHECK` на таблице плюс единственная точка изменения счётчика |
| Билет действителен только со временем прохода | `CHECK (status <> 'Использован' OR used_at IS NOT NULL)` |
| Возврат заявки обоснован | `CHECK` на длину комментария (не короче 10 символов) |

**Идемпотентность.** Повторная отметка билета не перезаписывает время и не создаёт
дубль: `ticket.qr_payload` уникален, ответ помечается `alreadyMarked: true`.
Пакетная отметка после работы без сети принимает до 500 записей за вызов.

**Доступность.** 99,5 % в месяц, окно обслуживания — воскресенье 02:00–04:00.
RPO 15 минут, RTO 1 час.

## 4. Производительность

| Операция | Критерий |
|---|---|
| Каталог, список мероприятий | P95 ≤ 400 мс, P99 ≤ 900 мс при 200 запросах/с |
| Запись до появления билета | ≤ 800 мс |
| Проверка QR без сети | ≤ 300 мс (локальная проверка подписи) |
| Отчёт по мероприятию | ≤ 2 с при 5 000 записей |
| Выгрузка 1 000 участников | ≤ 5 с, потоковая запись без буфера в памяти |

## 5. Ограничения API

**Лимиты.** 100 запросов в минуту на пользователя, 20 в минуту на IP для
анонимных чтений; при превышении — `429 RATE_LIMITED` с заголовком `Retry-After`.

**Версионирование.** Версия в пути (`/api/v1`). Ломающие изменения — только в
`/api/v2`; старые поля не удаляются, а помечаются `deprecated` на один релиз.

**Формат ошибок.** Тело всегда содержит `code`, `message`, `field`, `traceId`.
`traceId` совпадает с записью в логе — по нему поддержка находит запрос.

## 6. Совместимость

| Клиент | Требование |
|---|---|
| Мобильное приложение | iOS 15+, Android 9+ |
| Веб-приложение | Chrome, Firefox, Safari, Edge — две последние версии |
| LLM-клиент (MCP) | Поддержка MCP 1.x и 2.x; проверено на Python SDK 2.3 |
| PostgreSQL | 15 и выше (нужны `gen_random_uuid`, частичные индексы, `jsonb`) |

Кодировка — UTF-8 везде, включая CSV (с BOM для Excel). Даты в API — ISO 8601 с
указанием смещения; в интерфейсе — `ДД.ММ.ГГГГ`, время — `ЧЧ:ММ`.
