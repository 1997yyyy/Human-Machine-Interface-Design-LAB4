# Задачи для GitHub Projects

Готовые тексты для issues: копировать блок «Заголовок» в поле Title, блок «Тело» — в тело issue.
Порядок: сначала создать шесть issues, потом один проект с импортом items из репозитория.

---

## Issue 1

**Заголовок**

```
Задание 1. Модель требований и реестр вариантов использования
```

**Тело**

```
Дополнить модель требований ЛР № 3 до уровня API: у каждой пользовательской истории
должен быть вариант использования, у каждого варианта — актор, у каждого варианта —
конечная точка в API.

Что сделано:
- 16 пользовательских историй (US-01…US-16), 20 вариантов использования (UC-01…UC-23,
  нумерация ЛР № 3 сохранена), 4 актора: гость, студент, организатор, администратор;
- добавлены истории US-13…US-16 для функций, которых не было в ЛР № 3: пакетная
  отметка явки, настройка уведомлений, отчёт по мероприятию, управление клубами;
- реестр «Актор → User Story → Use Case» — по строке на каждый вариант использования;
- проверка полноты: 20/20 вариантов имеют актора и конечную точку.

Результат: docs/02-requirements.md, wiki «Функциональные требования».

Критерии приёмки:
- [ ] каждая история связана хотя бы с одним вариантом использования;
- [ ] каждый вариант имеет актора и строку в таблице соответствия API (задание 3);
- [ ] таблица реестра содержит номера UC, а не только названия.
```

## Issue 2

**Заголовок**

```
Задание 2. Логическая и физическая модель базы данных
```

**Тело**

```
Превратить ER-диаграмму ЛР № 3 в физическую модель PostgreSQL: типы, ограничения,
индексы, триггеры, плюс словарь полей и работающий DDL.

Что сделано:
- 14 таблиц, 13 перечислений, 103 поля, 3 триггера-инварианта, 7 уникальных индексов;
- словарь полей: «Сущность | Таблица БД | Поле | Смысл поля | Тип данных»;
- счётчик занятых мест session.taken меняется только триггером — правило
  0 ≤ taken ≤ capacity нельзя нарушить ни одним запросом;
- db/schema.sql и db/seed.sql выполнены на PostgreSQL 16 в Docker: 34 строки данных;
- db/verify.sql — 15 проверок ограничений и триггеров внутри транзакции с откатом,
  все пройдены (15/15).

Результат: db/schema.sql, db/seed.sql, db/verify.sql, assets/erd-physical.png,
docs/05-database.md, страница сайта db/index.html.

Критерии приёмки:
- [ ] DDL применяется на чистой базе без ошибок;
- [ ] ограничения проверены запросами, а не только объявлены;
- [ ] ER-диаграмма и словарь полей собраны из одного источника (tools/gen_db.py).
```

```

**Тело**

```
Сопоставить сущности базы данных с ресурсами REST и связать каждый вариант

- [ ] каждый вариант использования из задания 1 имеет конечную точку;
- [ ] для каждой точки указано, нужен ли токен;

```

**Тело**

```
Описать API контрактом OpenAPI 3.0.3 и проверить его на Mock-сервере.

Критерии приёмки:
- [ ] спецификация валидна;
- [ ] Mock отвечает на все три сценария;
- [ ] скриншоты и ссылка на коллекцию приложены к issue и в wiki.
